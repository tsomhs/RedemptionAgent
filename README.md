# Redemptions agent

Κάθε μήνα πρέπει να μάθουμε από τους συνεργάτες του προγράμματος ΔΕΗ myRewards
Coupons πόσα κουπόνια εξαργυρώθηκαν. Μέχρι τώρα αυτό γινόταν με το χέρι: emails,
υπενθυμίσεις, διάβασμα απαντήσεων, πέρασμα των αριθμών σε ένα Excel. Ο agent
κάνει αυτή τη δουλειά μόνος του και δείχνει το αποτέλεσμα σε ένα dashboard.

Οι προδιαγραφές της ομάδας είναι στο `docs/Warply_Engage_AI_Redemptions_Brief.docx`.

## Γρήγορη εκκίνηση

Χρειάζεται Python 3.11 ή νεότερη. Σε Linux, macOS ή WSL:

```
make install
make run
```

Ανοίξτε το http://127.0.0.1:8765 στον browser. Σταματά με Ctrl+C.

Την πρώτη φορά ο agent φτιάχνει μια **δοκιμαστική βάση με επινοημένα δεδομένα**
(`data/demo.db`), ώστε να υπάρχει κάτι να δείτε: οκτώ συνεργάτες που δεν
υπάρχουν, έξι μήνες με νούμερα και έναν μήνα σε εξέλιξη, με ένα αίτημα σε κάθε
κατάσταση. Κανένα email δεν στέλνεται και δεν χρειάζεται καμία ρύθμιση.

Αν το `make install` σταματήσει με μήνυμα για το `venv`, λείπει ένα πακέτο του
συστήματος: σε Ubuntu ή Debian, `sudo apt install python3-venv`.

Σε Windows (PowerShell) είναι τα ίδια βήματα γραμμένα αναλυτικά:

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python main.py
```

## Πώς δουλεύει

1. **Παίρνει το αρχείο του μήνα.** Είναι το Excel από το Engage που λέει πόσα
   κουπόνια δόθηκαν σε κάθε προσφορά.
2. **Στέλνει ένα email σε κάθε συνεργάτη** και ρωτά πόσα κουπόνια εξαργυρώθηκαν
   στις προσφορές του.
3. **Θυμίζει σε όσους δεν απάντησαν**, έως τρεις φορές, μία την εβδομάδα.
4. **Διαβάζει τις απαντήσεις.** Αν ο συνεργάτης απάντησε στη μορφή που του
   ζητήσαμε, ο αριθμός καταχωρείται αμέσως. Αν έγραψε ελεύθερο κείμενο ή έστειλε
   αρχείο, το διαβάζει ένα μοντέλο AI.
5. **Ό,τι δεν είναι σαφές το αφήνει σε άνθρωπο.** Ο agent δεν μαντεύει ποτέ
   αριθμό. Ένα «περίπου 15», ένα σύνολο χωρίς ανάλυση ή ένα email που γύρισε
   πίσω πηγαίνουν στην καρτέλα «Προς έλεγχο».
6. **Δείχνει τα αποτελέσματα** στο dashboard και τα δίνει σε Excel, στη μορφή
   του report που έφτιαχνε η ομάδα.

Δύο κανόνες ισχύουν παντού. Αν κάποιος δεν απάντησε, το κελί μένει κενό και δεν
γίνεται 0. Και κάθε αριθμός δείχνει από ποιο email προήλθε.

Ο agent κρατά τα δεδομένα του σε δικό του αρχείο βάσης, μέσα στον φάκελο `data/`.
Δεν γράφει τίποτα στο Engage.

## Το dashboard

- **Επισκόπηση**: τα σύνολα, η εικόνα ανά μήνα, οι συνεργάτες και οι προσφορές με
  τις περισσότερες εξαργυρώσεις.
- **Αναλυτικά**: μία γραμμή για κάθε προσφορά και μήνα. Το κουμπί «Λήψη Excel»
  κατεβάζει ό,τι δείχνουν τα φίλτρα.
- **Προς έλεγχο**: ό,τι χρειάζεται άνθρωπο. Απαντήσεις που δεν ήταν σαφείς
  (βάζουμε εμείς τον αριθμό, ζητάμε διευκρίνιση, ή λέμε ότι δεν χρειάζεται
  ενέργεια), emails που δεν παραδόθηκαν (διορθώνουμε τη διεύθυνση και
  ξαναστέλνουμε) και emails που δεν ταιριάζουν σε κανένα αίτημα.
- **Αιτήματα**: κάθε αίτημα με την κατάστασή του και όλη την αλληλογραφία.
- **Ρυθμίσεις**: τι κάνει ο agent μόνος του. Ξεκινά με τον αυτοματισμό κλειστό.
  Όταν ανοίξει, ο agent ξεκινά τον κύκλο την πρώτη εργάσιμη κάθε μήνα, διαβάζει
  τα εισερχόμενα κάθε μισή ώρα και στέλνει τις υπενθυμίσεις κάθε πρωί. Από εδώ
  αλλάζουν η ημέρα και η ώρα, οι υπενθυμίσεις, οι αργίες, και αν τα emails
  χρειάζονται έγκριση πριν φύγουν. Στο κάτω μέρος φαίνεται τι έκανε.

## Από τη δοκιμαστική βάση στα πραγματικά δεδομένα

Οι ρυθμίσεις είναι στο αρχείο `.env`, που το φτιάχνει το `make install`. Κάθε
γραμμή του έχει από πάνω την εξήγησή της.

1. **Βάση.** Αλλάξτε το `AGENT_DB` από `data/demo.db` σε `data/agent.db`. Η
   δοκιμαστική βάση μένει άθικτη στο δικό της αρχείο.
2. **Mailbox.** Συμπληρώστε τον λογαριασμό από τον οποίο θα στέλνει και θα
   διαβάζει ο agent (`MAIL_USER`, `MAIL_PASSWORD`, `MAIL_FROM`).
3. **Συνεργάτες.** Το `python main.py contacts-export docs/contacts.xlsx` φτιάχνει
   ένα Excel με όλες τις προσφορές. Συμπληρώνουμε σε ποιον συνεργάτη ανήκει η
   καθεμία και το email του, και το φορτώνουμε με `python main.py contacts-import
   docs/contacts.xlsx`. Το ίδιο κάνουμε όποτε αλλάζει κάτι.
4. **Το αρχείο κάθε μήνα.** Το αφήνουμε στον φάκελο `input/` με τον μήνα στο
   όνομά του, π.χ. `input/assignments_2026-11.xlsx`. Ο αυτοματισμός το βρίσκει
   μόνος του· αν λείπει, περιμένει και το γράφει στις Ρυθμίσεις. Αφού διαβαστεί,
   δεν χρειάζεται πια.
5. **AI (προαιρετικά).** Με ένα κλειδί στο `.env` διαβάζονται και οι απαντήσεις
   σε ελεύθερο κείμενο. Χωρίς κλειδί, αυτές απλώς περιμένουν στο «Προς έλεγχο».

### Η ασφάλεια των δοκιμών

Στο `.env` υπάρχει η ρύθμιση `MAIL_MODE`. Όσο είναι `test`, ο agent αρνείται να
στείλει email σε οποιαδήποτε διεύθυνση δεν είναι στη λίστα `ALLOWED_RECIPIENTS`,
οπότε δεν μπορεί να φύγει κατά λάθος email σε πραγματικό συνεργάτη. Γίνεται
`live` μόνο όταν είμαστε έτοιμοι.

## Εντολές

Το `make run` είναι το ίδιο με `python main.py`. Κάθε βήμα γίνεται και με το χέρι.
Ενεργοποιούμε πρώτα το περιβάλλον (`source .venv/bin/activate`) και μετά:

```
python main.py ingest input/assignments_2026-10.xlsx --month 2026-10   # αρχείο του μήνα
python main.py plan --month 2026-10                                    # ετοιμάζει τα emails
python main.py send --month 2026-10                                    # τα στέλνει
python main.py fetch                                                   # διαβάζει τις απαντήσεις
python main.py followups                                               # στέλνει υπενθυμίσεις
python main.py status --month 2026-10                                  # πού βρισκόμαστε
python main.py --help                                                  # όλες οι εντολές
```

Καμία εντολή δεν στέλνει ή μετρά κάτι δεύτερη φορά, όσες φορές κι αν τρέξει.

## Έλεγχοι

```
make test
```

Τρέχει τους αυτόματους ελέγχους. Δουλεύουν σε προσωρινές βάσεις και δεν στέλνουν
κανένα email. Η τελευταία γραμμή λέει αν πέρασαν όλοι.

## Τι υπάρχει στον φάκελο

| Φάκελος ή αρχείο | Τι είναι |
|---|---|
| `main.py` | Από εδώ ξεκινά ο agent |
| `agent/` | Ο κώδικας |
| `tests/` | Οι αυτόματοι έλεγχοι |
| `docs/` | Το brief της ομάδας, και το `contacts.xlsx` όταν φτιαχτεί |
| `Makefile` | Οι συντομεύσεις `make install`, `make run`, `make test` |
| `requirements.txt` | Οι βιβλιοθήκες που χρειάζεται |
| `.env.example` | Υπόδειγμα ρυθμίσεων· το `make install` το αντιγράφει σε `.env` |

Τρία πράγματα φτιάχνονται στον υπολογιστή σας και δεν ανεβαίνουν ποτέ στο git: ο
φάκελος `data/` με τη βάση και τα συνημμένα που έλαβε ο agent, ο φάκελος `input/`
με το αρχείο του μήνα, και το `.env` με τους κωδικούς. Το ίδιο ισχύει για κάθε
αρχείο Excel, γιατί έχουν στοιχεία συνεργατών.

Μέσα στο `agent/` κάθε αρχείο κάνει ένα πράγμα. Με τη σειρά που συμβαίνουν:

| Αρχείο | Τι κάνει |
|---|---|
| `assignments.py` | Διαβάζει το αρχείο του μήνα |
| `contacts.py` | Διαβάζει συνεργάτες και emails |
| `prepare_requests.py` | Γράφει το email κάθε συνεργάτη |
| `mail.py` | Στέλνει emails και υπενθυμίσεις, παραλαμβάνει απαντήσεις και ανεπίδοτα |
| `replies.py` | Βγάζει τους αριθμούς από τις απαντήσεις και τους καταχωρεί |
| `ai_reader.py` | Διαβάζει με AI το ελεύθερο κείμενο και τα συνημμένα |
| `review.py` | Η ουρά ελέγχου |
| `report.py` | Οι πίνακες του dashboard και το Excel |
| `web.py`, `dashboard.html` | Το dashboard |
| `automation.py`, `settings.py`, `workdays.py` | Ο χρονοπρογραμματιστής, οι ρυθμίσεις του, οι εργάσιμες και οι αργίες |
| `__main__.py`, `config.py`, `db.py` | Οι εντολές, η ανάγνωση του `.env`, οι πίνακες της βάσης |
| `old_report.py` | Φορτώνει το παλιό χειροκίνητο report της ομάδας |
| `demo.py` | Φτιάχνει τη δοκιμαστική βάση |

## Τι δεν έχει γίνει ακόμη

- Το αρχείο του μήνα το βάζει κάποιος με το χέρι στο `input/`. Η αυτόματη άντλησή
  του από το Engage δεν έχει γραφτεί.
- Ο agent τρέχει όσο είναι ανοιχτό το `make run`. Για να δουλεύει κάθε μέρα μόνος
  του χρειάζεται έναν υπολογιστή που μένει ανοιχτός.
- Το dashboard δεν έχει σύνδεση χρηστών, γι' αυτό ανοίγει μόνο από τον ίδιο
  υπολογιστή.
- Υπάρχει ένα κείμενο email για όλα τα προγράμματα, γραμμένο μέσα στον κώδικα.
- Αν ένας συνεργάτης δώσει αριθμούς για άλλον μήνα από αυτόν που ρωτήσαμε,
  πηγαίνουν για έλεγχο· δεν καταχωρούνται αυτόματα σε εκείνον τον μήνα.
- Η ανάγνωση με AI έχει δοκιμαστεί μόνο με απαντήσεις που γράψαμε εμείς, όχι με
  πραγματικά emails συνεργατών.
